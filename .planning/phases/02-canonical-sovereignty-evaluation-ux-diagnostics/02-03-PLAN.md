<objective>
**As an** Architect, **I want to** open a BusinessCapability or DataObject's sovereignty detail and see its own explicit chain findings — with a clear visual split between "this element itself is the problem" and "something weaker downstream affects it" — **so that** I can act on the actual root cause instead of a single inherited score that hides where the break really is.

This plan retires the last consumer of the old inheritance model (`client/src/components/sovereignty/utils.ts`, deleted per D-07) and rewrites both sovereignty detail views to render 02-01's canonical `sovereigntyAnalysis` findings.

Purpose: close SUX-01/SUX-02 by making the explainable-findings model visible where architects actually look — the element detail view.
Output: rewritten `SovereigntyCapabilityView.tsx`/`SovereigntyDataView.tsx`, a new canonical `sovereigntyDetail.ts` query, deleted `utils.ts`, new copy strings in both locale files.
</objective>
