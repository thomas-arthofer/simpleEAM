<objective>
**As an** Architect, **I want to** see each element's sovereignty rating evaluated from its own explicit achieved evidence — compared explicitly against the chain of requirements above it, down to Application/AIComponent/Infrastructure — **so that** I can trust the sovereignty assessment instead of it silently inheriting a value nobody actually entered (per ROADMAP.md Phase 2 Goal).

This plan builds the canonical `server/src/sovereignty/` evaluation module — the single backend-owned engine that replaces both diverging implementations (`client/src/components/sovereignty/utils.ts` inheritance and `ai-server/temporal/sovereignty/activities.ts`'s formula, retired in plans 02-04/02-03). It also wires the module onto the existing `@neo4j/graphql` server as a new, additive `sovereigntyAnalysis` query, proving the first-ever custom-resolver path in this codebase end-to-end.

Purpose: establish one authoritative place that reads `sovereigntyReq*`/`sovereigntyAch*` fields, classifies RED/YELLOW/GREY/GREEN per `eam-konzept.md` §3, and can be called identically by GraphQL resolvers, batch marker projection (02-02), and the Temporal rollup (02-03).
Output: `server/src/sovereignty/{types,repository,evaluator}.ts`, `server/src/sovereignty/graphql/resolvers.ts`, `server/jest.config.js`, and a passing fixture-based Jest suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Client → GraphQL `sovereigntyAnalysis` resolver | Untrusted `companyId`/`rootType`/`rootId` arguments arrive from any authenticated client; this resolver runs OUTSIDE the declarative `@authorization` directive pipeline every other type in `schema.graphql` uses |
| Resolver → Neo4j | The resolver builds a parameterized Cypher `WHERE` clause from JWT-derived `company_ids`; a bug here is the only thing standing between a caller and cross-company sovereignty data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure / Elevation of Privilege | `server/src/sovereignty/graphql/resolvers.ts::sovereigntyAnalysis` | high | mitigate | Resolver manually decodes `context.token`, extracts `company_ids`/`roles`, and rejects before querying unless `args.companyId ∈ company_ids` or `roles.includes('admin')` — Task 1 `<action>` implements this explicitly; `repository.ts`'s Cypher additionally filters `WHERE $isAdmin OR c.id IN $companyIds` as defense in depth (never trust the resolver-level check alone) |
| T-02-02 | Tampering | `server/src/sovereignty/repository.ts` Cypher construction | high | mitigate | All Cypher parameters (`$capabilityId`, `$companyIds`, `$isAdmin`) are passed via the driver's parameter API, never string-concatenated into the query text |
| T-02-03 | Denial of Service | `server/src/sovereignty/evaluator.ts` cycle traversal | medium | mitigate | D-03 visited-set guard (Task 2) bounds traversal to the number of distinct nodes in the chain, preventing infinite recursion on cyclic data |
