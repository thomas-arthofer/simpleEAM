<objective>
**As an** Architect, **I want to** see the Company-level sovereignty score reflect the same explicit chain evaluation used everywhere else — including correctly reflecting a mostly-GREY rollout as a low/unknown score rather than silently excluding ungraded elements — **so that** the dashboard-level number I trust is produced by the same rules as the detail view I already trust (SOV-05).

This plan retires `ai-server/temporal/sovereignty/activities.ts`'s standalone maturity-averaging formula (`MATURITY_SCORE`/`REQ_DIMS`/`ACH_DIMS`/`fetchSovereigntyReqEntities`/`fetchSovereigntyAchEntities`/the `.filter((s): s is number => s !== null)` step in `computeSovereigntyScores`) and replaces it with a call into a new server-side `companyRollup.ts` that batches 02-01's canonical evaluator across every BusinessCapability/DataObject a company owns.

Purpose: close the last remaining consumer of the pre-canonical scoring logic (Temporal), completing SOV-05's "one evaluator, every call site" requirement.
Output: `server/src/sovereignty/companyRollup.ts`, a new `sovereigntyCompanyRollup` GraphQL query, and a rewired `ai-server/temporal/sovereignty/activities.ts`/`workflow.ts`.
</objective>
