<objective>
Fix D-02/D-03/D-04: `sovereigntyMarkers.ts`'s `createMarkerEllipses` computes fill/ring ellipse `x`/`y` once, at sync time, from the main element's position. The ellipses are only visually grouped (`groupIds: [mainElement.id]`), which only moves them together on a multi-selection drag — dragging just the main element alone leaves its markers behind at the old position. This plan adds a lightweight in-place reposition path that runs on every `onChange` event in `ExcalidrawWrapper.tsx` (D-02), mutating the existing fill/ring elements' `x`/`y`/`version`/`versionNonce`/`updated` in place (D-03), scoped only to main elements that currently carry a marker pair (D-04) — never touching `createMarkerEllipses`/`applySovereigntyMarkers`, which remain the sync-time (initial/resync) path.

Purpose: make dragged elements' sovereignty markers visually trustworthy during editing, not just immediately after a sync — closing the second UAT-reported gap in Phase 2's diagram marker feature (SUX-03/SUX-04).
Output: two new exported functions in `sovereigntyMarkers.ts` (`repositionMarkerEllipses`, `repositionAllMarkerEllipses`) and a wiring change inside `ExcalidrawWrapper.tsx`'s existing `handleChange` callback.
</objective>

## Artifacts This Phase Produces (this plan)

- `repositionMarkerEllipses(mainElement, fillEllipse, ringEllipse): { fillEllipse, ringEllipse } | null` — new export in `client/src/components/diagrams/utils/sovereigntyMarkers.ts`. Recomputes the same top-right-anchor geometry `createMarkerEllipses` uses and returns mutated copies (same `id`, updated `x`/`y`/`version`/`versionNonce`/`updated`) of the two ellipses, or `null` if the recomputed position is unchanged.
- `repositionAllMarkerEllipses(elements): { elements, changed: boolean }` — new export in the same file. Scans `elements` once for main database elements that have an existing fill+ring marker pair (per D-04), calls `repositionMarkerEllipses` for each, and returns either the original `elements` reference with `changed: false` (no marker pair needed repositioning) or a new array with the repositioned pairs substituted in place and `changed: true`.

No other new exports. `createMarkerEllipses`, `applySovereigntyMarkers`, `fetchSovereigntyMarkersForDiagram`, `syncSovereigntyMarkers` are unchanged.
