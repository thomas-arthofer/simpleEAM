<objective>
Fix D-01: the localStorage full-page-reload (F5) scene-restore path in `useDiagramState` (`client/src/components/diagrams/state/DiagramState.ts`) currently calls only the local, synchronous `restoreSceneData` reshaping helper and never calls `syncDiagramOnOpen`/`syncSovereigntyMarkers` — so sovereignty markers (and the DB name/missing-element sync `handleOpenDiagram` already performs) silently disappear on a raw browser reload, reappearing only via cross-page navigation or a manual Ctrl+R resync. This plan makes the restore path run the identical `syncDiagramOnOpen` pipeline `handleOpenDiagram` runs, so restore behavior is indistinguishable regardless of how the diagram was opened.

Purpose: close the UAT-reported gap so sovereignty markers and DB sync survive an ordinary F5 reload, matching Phase 2's SUX-03/SUX-04 guarantee that diagram markers always reflect the canonical evaluation result.
Output: `client/src/components/diagrams/state/DiagramState.ts`'s scene-restore effect calls `syncDiagramOnOpen` before restoring the scene into Excalidraw, with fail-soft error handling identical to `handleOpenDiagram`'s.
</objective>

No new exported symbols. No new files, no new exports.
