# Phase 02.1 Plan 01: Fix F5 Reload Sovereignty Sync Gap Summary

**F5/full-page reload now runs the exact same `syncDiagramOnOpen` pipeline `handleOpenDiagram` uses, so sovereignty markers survive a raw browser reload instead of only reappearing via cross-page navigation or a manual Ctrl+R resync.**

## Accomplishments

- `useDiagramState`'s localStorage scene-restore effect (`DiagramState.ts`) now calls `syncDiagramOnOpen(apolloClient, currentScene, { enabled: featureFlags.Sovereignty, companyId: selectedCompanyId })` before restoring the scene into Excalidraw — the identical options shape `handleOpenDiagram` already uses.
- Added `useApolloClient` (from `@apollo/client`) and `useFeatureFlags` (from `@/lib/feature-flags`) hook calls to `useDiagramState`, matching `useDiagramHandlers`'s exact call shape.
- Fail-soft error handling: a `try/catch` around the sync call logs a `console.warn` and falls back to the un-synced `currentScene` on failure — the scene still restores from localStorage without markers rather than throwing or blocking restoration.
- No changes to `sceneRestoredRef` guard logic, `openDiagramId` early-return gating, or viewport restoration — only the data feeding `restoreSceneData` changed (`currentScene` → `syncedScene`), plus wrapping the `setTimeout` callback as `async` to allow the `await`.
