## Deviations from Plan

### Auto-fixed Issues

**1. [Blocking] `neo4j` `mem_limit` too low for its own configured heap/pagecache**

- **Found during:** Post-commit verification of the running stack (`docker compose up -d`).
- **Issue:** `docker-compose.override.yml` set `neo4j: mem_limit: 2g`, but `.env`'s `NEO4J_PAGECACHE_MEMORY=1G` + `NEO4J_HEAP_MAX_SIZE=2G` already require more than that inside the container's cgroup, so neo4j refused to start and crash-looped continuously.
- **Fix:** Raised `mem_limit` to `4g` (host has 12GB+ free, safe headroom).
- **Files modified:** `docker-compose.override.yml`
- **Verification:** neo4j stayed up, `server` reconnected successfully, `docker ps` showed no restarting/exited containers.
- **Committed in:** this session's commit.

## Issues Encountered

- Task 3's browser login checkpoint required actions only the developer could perform (trusting `local/certs/rootCA.pem`, interactive Keycloak login) — confirmed working on 2026-07-27.
- After login, `api.example.com/graphql` initially failed in the browser console with `ERR_CERT_AUTHORITY_INVALID` (repeated). Root cause: Chrome trusts a self-signed/local-CA cert **per origin**, not per certificate — the developer had only accepted the warning for `eam`/`auth` (via the login redirect), not for `api` (contacted only via background XHR/`fetch`, never navigated to directly). Documented the fix (open each origin once, or import the CA into the OS/browser trust store) as a new Troubleshooting section in `docs/lokale-https-domains.md`, plus an explicit numbered checklist of all 6 URLs to open.
