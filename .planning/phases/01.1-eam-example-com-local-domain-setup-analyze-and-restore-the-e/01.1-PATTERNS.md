## Pattern Assignments

### `traefik.local.yml` (new, standalone Compose snippet)

**No direct analog exists** — this repo has exactly one Compose file (`compose.yml`) and no precedent for a second, standalone/optional one. The planner should mirror `compose.yml`'s own conventions for the pieces that carry over (external network reference, `${VAR}` interpolation, quoting style), scaled down to a single service.

**External network declaration pattern** (`compose.yml` lines 521–524):
```yaml
networks:
  eam-network:
    driver: bridge
  traefik:
    external: true
```
→ `traefik.local.yml` needs only the `traefik: external: true` half (no `eam-network`, since this file's sole service must join the pre-existing shared network, not create a new one — see CONTEXT.md D-04/D-05).

**Service `networks:` attachment pattern** (`compose.yml` lines 35–37, repeated per service, e.g. `neo4j`):
```yaml
    networks:
      - eam-network
      - ${TRAEFIK_NETWORK}
```
→ For the new Traefik service, this becomes a *mapping* form (not a list) because network **aliases** are required (RESEARCH.md Pattern 2):
```yaml
    networks:
      traefik:
        aliases:
          - eam.example.com
          - api.example.com
          # ... one per *_SUBDOMAIN
```
This is a variant of the existing list-form network attachment, not a new convention — same `${TRAEFIK_NETWORK}`-style reference, expanded to mapping form only because `aliases:` requires it.

**`${VAR}` interpolation & quoting style** (`compose.yml` lines 40–46, keycloak labels):
```yaml
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.${COMPOSE_PROJECT_NAME:-nextgen-eam}-keycloak.rule=Host(`${AUTH_SUBDOMAIN}.${BASE_DOMAIN}`)"
```
→ Not directly reused (the new file is a Traefik *provider*, not a routed service — it has no `traefik.enable`/router labels of its own), but confirms repo convention: double-quoted YAML strings, `${VAR:-default}` fallback syntax, backtick-quoted `Host()` rule values. Any comments/instructions embedded in `traefik.local.yml` should use the same `${VAR}` referencing style as `compose.yml` (e.g. reference `${TRAEFIK_NETWORK}` rather than hardcoding `traefik`, for consistency — RESEARCH.md's own example hardcodes `traefik`/`traefik:v3.7.8`, which is acceptable since this file is optional/standalone and not sourced by `.env`, but planner should stay consistent one way or the other).

**Top-of-file comment-header convention** — no existing standalone-file precedent in this repo; use the same terse, instructional comment-block style already established at the top of `env.template` (see below) rather than inventing a new style: short purpose line + explicit start/stop commands, e.g.:
```yaml
# traefik.local.yml — optional, standalone local reverse proxy.
# Not referenced by compose.yml (see README "Optional Path").
# Start:   docker compose -f traefik.local.yml up -d
# Stop:    docker compose -f traefik.local.yml down
```
This mirrors `env.template`'s header block style (see env.template pattern below): short bolded/hash-banner purpose statement followed by usage instructions, not prose paragraphs.

```markdown
5. **Optional Path: Traefik/HTTPS parity (not required)**

Use this only when you need ingress-like parity in local setups.
Nicht erforderlich fuer Supported Path.
```
→ Preserve this exact bilingual guardrail pattern (English lead sentence + short German "Nicht erforderlich..." disclaimer line) when adding restoration steps — this is Phase 1's established "don't blur Supported vs Optional" convention (CONTEXT.md D-08).
```markdown
Optional prerequisites:

- Running Traefik instance with configured docker network
- DNS/hosts entries for service hostnames
```

### `env.template` (inline comment additions only, no new variables)

**Analog:** the existing comment conventions directly above `TRAEFIK_CERTRESOLVER`/`TRAEFIK_NETWORK`/`KEYCLOAK_URL`.

**Inline "Optional Path" qualifier comment style** (env.template lines ~38–44):
```bash
# Traefik certificate resolver name (for automatic HTTPS certificates)
# Optional Traefik/HTTPS parity variable. Leave empty if not using Traefik.
TRAEFIK_CERTRESOLVER=my-traefik-cert-resolver

# Docker network name for Traefik reverse proxy
# Optional Traefik/HTTPS parity variable.
TRAEFIK_NETWORK=traefik
```
→ Any clarifying comment added for local restoration (e.g. noting the value should be emptied for local self-signed use, per CONTEXT.md D-06/RESEARCH.md Open Question 2) should follow this exact two-line pattern: a plain description line, then an `# Optional Traefik/HTTPS parity variable. ...` qualifier line — do not restructure into a longer paragraph. Per RESEARCH.md's Open Question 2 recommendation, leave the `env.template` **default value** unchanged (illustrative placeholder) and only add/adjust the comment text.

**Dual-path qualifier style** (env.template lines ~124–127, `KEYCLOAK_URL`):
```bash
# Full Keycloak URL (including protocol and subdomain)
# Supported Path can use localhost port access for runtime checks.
# Optional Path can use https://auth.<BASE_DOMAIN> behind Traefik.
KEYCLOAK_URL=https://${AUTH_SUBDOMAIN}.${BASE_DOMAIN}
```
→ This is the established pattern for documenting "Supported Path vs Optional Path" behavior differences inline. If the plan adds a comment clarifying the login caveat (CONTEXT.md D-09) near `KEYCLOAK_URL` or `TRAEFIK_CERTRESOLVER`, reuse this exact two-line "Supported Path ... / Optional Path ..." phrasing convention rather than inventing new wording.

## Shared Patterns

### Supported-vs-Optional guardrail phrasing
**Source:** `README.md` line 104 (`Nicht erforderlich fuer Supported Path.`) and `env.template` general-settings header (lines ~26–35: "Supported Path (localhost-first) minimums... Optional Path (Traefik/HTTPS parity)... Not required for Supported Path").
**Apply to:** All README.md and env.template edits in this phase.
This bilingual/dual-path guardrail phrasing is the one cross-cutting convention that spans both files. Any new text added by this phase must preserve it verbatim in style (short, declarative, explicitly naming "Supported Path" / "Optional Path") rather than introducing new terminology for the same distinction.

### `${VAR}` / `${VAR:-default}` interpolation
**Source:** `compose.yml` (all label blocks, e.g. lines 24–31, 40–47, 502–518) and `env.template` (`KEYCLOAK_URL=https://${AUTH_SUBDOMAIN}.${BASE_DOMAIN}`).
**Apply to:** `traefik.local.yml` and any new `.env`/README command examples referencing hostnames.
Keep hostname construction expressed as `${SUBDOMAIN}.${BASE_DOMAIN}` wherever the surrounding file already uses variables, and literal `eam.example.com`-style FQDNs only in the standalone `traefik.local.yml` (which is not sourced by `.env`) and in prose/manual-step instructions (e.g. `/etc/hosts` lines), matching RESEARCH.md's own Code Examples section.
