## Phase Boundary

Analyze why the `eam.example.com` hostname-routed local setup no longer works, and restore it so the Docker Compose stack — most importantly Keycloak-backed login — functions correctly when accessed via `https://eam.example.com`. This is a narrow, urgent restoration of a previously-working local routing path, not a redesign of the deployment model and not a reversal of Phase 1's localhost-first "Supported Path" decision.

</domain>

<decisions>
## Implementation Decisions

### Root cause & goal scope
- **D-01:** The urgent driver is a real functional break, not just missing docs: `auth/src/realm-export.json` hardcodes the Keycloak client's `redirectUris`/`webOrigins` to `https://eam.example.com/*` only — there is no `localhost:3000` entry. SSO login through the Phase-1 "Supported Path" (localhost-first) is therefore expected to fail today. Restoring `eam.example.com` routing is what makes login work again, and that is the concrete success condition for this phase (not merely re-adding docs text).
- **D-02:** No changes to `auth/src/realm-export.json` / `k8s/realm-export.json` redirect URIs are in scope — they already correctly target `eam.example.com`, `api.example.com`, etc. The fix is entirely on the runtime/config/reverse-proxy side (`.env` values, hosts entry, Traefik), not the Keycloak realm data. This keeps the change footprint small and avoids brownfield data-model/auth risk.
- **D-03:** Adding a `localhost:3000` redirect URI to the dev realm so the Supported Path also supports login is a **related but separate improvement** — captured as a deferred idea, not part of this phase (see Deferred Ideas).

### Local Traefik provisioning
- **D-04:** No Traefik container currently runs locally, but the `traefik` Docker network is already declared `external: true` in `compose.yml` and 6 containers (client, server, keycloak, neo4j, excalidraw-room, temporal-ui) are already attached to it. This confirms the intended architecture: Traefik is an **external, developer-managed reverse proxy** (likely shared across the developer's other local projects, evidenced by the pre-existing `/etc/hosts` entry for an unrelated domain), not something this repo's `compose.yml` should own or start itself.
- **D-05:** Decision: do **not** add a Traefik service to `compose.yml`. Instead, document a copy-paste-able minimal local Traefik snippet (separate, clearly optional, e.g. in README's existing "Optional Path" section or a small standalone compose snippet) so a developer without an existing Traefik instance can stand one up, while developers with an existing shared Traefik instance just attach to the already-external `traefik` network. — **Reversibility:** reversible — pure documentation/optional snippet, no effect on the Supported Path or data model.

### TLS strategy
- **D-06:** Keycloak's redirect URI is `https://eam.example.com/*` (exact scheme `https`), so plain HTTP routing will not satisfy the OIDC redirect match. Decision: use Traefik's default self-signed certificate for the local `eam.example.com` router (leave `TRAEFIK_CERTRESOLVER` empty/unset for local use — a real ACME/Let's Encrypt challenge cannot succeed for `example.com` since it isn't a domain the developer controls). Document the expected browser self-signed-certificate warning as normal for this optional local path.
- **D-07:** `mkcert`-based trusted local certificates are noted as an optional future enhancement (removes the browser warning) but are **not required** for this phase — keep scope to "restore working routing," not "polish local TLS UX."

### Relationship to Phase 1 Supported Path
- **D-08:** Phase 1's "Supported Path (localhost-first)" default remains unchanged and is not reopened. `eam.example.com` stays documented as the "Optional Path: Traefik/HTTPS parity," per Phase 1's existing README structure — but this phase makes that optional path actually functional again (network already attached, correct `.env` values, hosts guidance, cert guidance) instead of aspirational/broken.
- **D-09:** Documentation must explicitly call out the login caveat: SSO via the Supported (localhost) Path does not currently work because of the Keycloak redirect URI configuration (D-01/D-02), and the Optional Path (`eam.example.com`) is the one that supports login end-to-end today.

### the agent's Discretion
- Exact wording/placement of the new README/env.template guidance, and the specific `.env` values to set as an example (`BASE_DOMAIN=example.com`, `CLIENT_SUBDOMAIN=eam`, `TRAEFIK_NETWORK=traefik`, `TRAEFIK_CERTRESOLVER=` empty) are left to research/planning to finalize against the live repo files.
- Whether a helper script (e.g., checking/adding the `/etc/hosts` entries for all subdomains: `eam`, `api`, `auth`, `neo4j`, `room`, `temporal`) is added versus purely documented as manual steps is left open for planning to decide based on effort/consistency with Phase 1's style (Phase 1 kept things documentation-first rather than script-first).

</decisions>

- Traefik routing is entirely label-driven per service in `compose.yml` (`traefik.http.routers.*`, `traefik.docker.network`) — any fix works within this existing label pattern, no new routing mechanism needed.
- Phase 1 established a strict Supported-vs-Optional split in docs (guardrail text "Nicht erforderlich für Supported Path") — new content must preserve that split, not blur it.

### Integration Points
- The `traefik` Docker network (external) is the seam between this repo's containers and whatever reverse proxy (existing external Traefik, or a newly-documented local one) terminates `eam.example.com` traffic.
- `.env`'s `BASE_DOMAIN`/`*_SUBDOMAIN` values are the seam between Compose labels and the Keycloak realm's hardcoded redirect URIs — these must line up exactly (`eam.example.com`, `api.example.com`) for login to work.
