# Phase 02.2 Plan 03: Retry-safe D-02 diff-detection + suppressOnChangeRef wiring Summary

**Closes G-02.2-3/G-02.2-5/G-02.2-6: a newly-dropped/duplicated/pasted main element's id is no longer marked "seen" until its sovereignty-marker sync is confirmed applied or confirmed impossible, and context-menu Delete/Duplicate/Paste now suppress the reentrant onChange like every other updateScene() call site — type-checked clean, manual UAT re-verification pending**

## Accomplishments

- `sovereigntyMarkers.ts` exports a new `hasAnyMarkerRoot(elements)` helper — the definitive "no markers possible for this diagram" signal, mirroring `fetchSovereigntyMarkersForDiagram`'s own zero-roots early-return. `isMarkerRoot`, `fetchSovereigntyMarkersForDiagram`, `applySovereigntyMarkers`, and `syncSovereigntyMarkers` are byte-for-byte unchanged.
- `ExcalidrawWrapper.tsx`'s `handleChange` no longer unconditionally overwrites `previouslySeenMainElementIdsRef.current` with the full current id set before the async sync fetch starts. It now retains already-confirmed ids still present on the diagram, drops ids no longer present, and only adds a newly-seen id inside the fire-and-forget IIFE's `try` block once `syncedElements` resolves and either that id got a fill/ring marker or `hasAnyMarkerRoot(syncedElements)` is false. A thrown error is caught and logged — the id simply stays unresolved and is retried on the next `handleChange`.
- `FullCustomContextMenu.tsx` now accepts `suppressOnChangeRef` as a prop (passed from `ExcalidrawWrapper`'s existing `<FullCustomContextMenu />` call site) and sets it `true` immediately before the `updateScene()` call in `handleDelete`, `handleDuplicate`, and `handlePaste` — matching the convention already used at every other `updateScene()` call site in the codebase. `handleCopy` (no `updateScene` call), `handleCut`, `handleBringToFront`, and `handleSendToBack` are untouched, per plan scope.
