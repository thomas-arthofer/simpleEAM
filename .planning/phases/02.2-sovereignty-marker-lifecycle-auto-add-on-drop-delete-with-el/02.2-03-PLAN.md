<objective>
Close three of the four Phase 02.2 UAT gaps whose root cause is confirmed: G-02.2-3 (auto-add-on-drop never live), G-02.2-6 (duplicate/copy/paste never gets markers live), and G-02.2-5 (context-menu Delete leaves marker orphans, plus its contribution to G-02.2-6). Both G-02.2-3 and G-02.2-6 share one root cause — `ExcalidrawWrapper.tsx`'s `handleChange` marks a newly-seen main element id "seen" in `previouslySeenMainElementIdsRef` synchronously, before its single fire-and-forget `syncSovereigntyMarkers()` attempt resolves, so a single empty/failed attempt is never retried. G-02.2-5 (and the context-menu-routed portion of G-02.2-6) stems from `FullCustomContextMenu.tsx`'s `handleDelete`/`handleDuplicate`/`handlePaste` calling `excalidrawAPI.updateScene()` directly without ever setting `suppressOnChangeRef.current = true` first, unlike every other `updateScene()` call site in the codebase.

Purpose: These are the two remaining confirmed root causes from `.planning/debug/sovereignty-marker-sync-not-live.md` blocking Phase 02.2 UAT sign-off. G-02.2-4 (native keyboard delete) is deliberately excluded from this plan — its root cause is unconfirmed and requires live browser instrumentation, handled separately in `02.2-04-PLAN.md`.
Output: New main elements (dropped, duplicated, copied, or pasted) reliably get their sovereignty markers live without a manual Ctrl+R, even across a transient first-attempt failure; context-menu Delete/Duplicate/Paste are consistent with the codebase's `suppressOnChangeRef` convention.
</objective>
