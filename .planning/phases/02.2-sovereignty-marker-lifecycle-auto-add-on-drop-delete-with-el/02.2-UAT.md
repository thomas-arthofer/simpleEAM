## Pending Manual Checks

1. **Non-selectability (D-04)**
   - Click directly on a fill/ring marker ellipse and attempt to drag it; then press Ctrl+A on a diagram with a marked main element.
   - **Expected:** No selection outline, cannot be dragged, excluded from Ctrl+A selection set.

2. **Reposition regression (D-04 / Phase 02.1)**
   - Drag a main element that already has fill/ring markers to a new position.
   - **Expected:** Markers live-reposition to track the main element's new top-right corner.

3. **Auto-add on drop (SOV-MARKER-AUTOADD / D-02)**
   - Drag a new main element from the library sidebar onto a diagram (Sovereignty flag on, company selected, at least one BusinessCapability/DataObject root).
   - **Expected:** Fill/ring markers appear shortly after drop, no manual Ctrl+R needed. Network tab shows exactly one new `sovereigntyMarkers` GraphQL request on the drop, none on subsequent drag/pan/edit of already-seen elements.

4. **Delete with element — native keyboard path (SOV-MARKER-DELETE / D-01 / D-03)**
   - Select a main element with markers, press keyboard Delete/Backspace.
   - **Expected:** Markers vanish in the same change (no orphans). Ctrl+Z: main element reappears. Ctrl+Z again if needed: markers reappear. **Record whether 1 or 2 presses were actually required.**

5. **Delete with element — context-menu path (SOV-MARKER-DELETE / D-01)**
   - Select a main element with markers, right-click → Delete (custom context menu, not native keyboard).
   - **Expected:** Both element and markers vanish together atomically. Exactly one Ctrl+Z restores both.

6. **Duplicate/copy/paste free coverage (D-01 triage)**
   - Duplicate a main element with markers via the context menu; separately copy/paste one.
   - **Expected:** The duplicate/pasted copy automatically gets its own fill/ring pair (via D-02's diff detection), with no marker-specific code path involved.
