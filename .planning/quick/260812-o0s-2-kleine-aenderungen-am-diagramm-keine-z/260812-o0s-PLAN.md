<objective>
Fix two diagram-editor bugs in `client/src/components/diagrams/utils/`:

1. **No line breaks in saved names (DIAG-NOWRAP-01):** A brand-new element typed from the ArchiMate palette can have its text saved to the database with an embedded newline/extra whitespace because `detectNewElements` only does `.trim()` (strips ends only) instead of full normalization. Separately, this codebase's own custom word-wrap helper (`wrapTextForExcalidraw`) manually inserts `\n` line breaks into labels built for library items, canvas-created elements, and renamed elements — the user wants NO line breaks introduced by our own logic at all.
2. **Infrastructure Type prefix (DIAG-INFRA-PREFIX-01):** For `elementType === 'infrastructure'`, every diagram label must read `"${InfrastructureTypeLabel} - ${name}"` (e.g. "Virtual Machine - SRLX0018") instead of the bare name, so it's clear what the (often cryptic) infrastructure name refers to.

Purpose: Diagram element names must save cleanly (no whitespace corruption) and infrastructure labels must be self-explanatory on the canvas.

Output: Three files modified — `newElementsUtils.ts` (normalization), `architectureElements.ts` (wrap disabled + new shared prefix helper + 2 call sites), `databaseSyncUtils.ts` (2 call sites reusing the shared helper).
</objective>
